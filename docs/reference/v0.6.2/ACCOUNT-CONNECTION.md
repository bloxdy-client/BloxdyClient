# Account and 3D character connection — 0.6.2

On 13 October 2026 the user explicitly restored official Bloxd windows for account/character actions. This supersedes the earlier 0.5.0 requirement against loading Bloxd even internally. The agent still never opens or operates a client or account.

Connect account creates an independent local session and opens the official Bloxd account screen. The user selects the chosen Google, Apple, Microsoft or Discord provider there and completes login. Allowed OAuth popups share that account session and have no capture preload. The first migrated account retains its previous session; additional accounts use separate persistent partitions and independent profiles. Account creation and available username changes use the official UI, operated by the user.

The model sync runs automatically after the user joins a game. It does not open My Character or change any player/menu state. It resolves the current local entity through the current public engine singleton and humanoid component, then reads only that entity’s body group and worn attachments. The body template provides an origin-independent fixed pose; transient first-person hiding, damage tint and gameplay armour are excluded. Cosmetic atlas layers and attachment textures are embedded in a bounded GLB. A stable asset fingerprint prevents incomplete first-frame exports and notices delayed clothing/accessory loads. Metadata and asset identity are checked again after asynchronous image reading. Leaving/rejoining resets the join epoch; changing an outfit updates its model automatically.

The Play area shows only the actual 3D model and username, or a short automatic-join placeholder before a model exists. Left mouse drag rotates, with front orientation corrected for saved models and no zoom or scale controls. There are no manual character sync controls. Source changes can require adapter maintenance. Real join extraction remains a user test; verification uses synthetic worlds and models without client/account starts.

Models live under `%LOCALAPPDATA%/BloxdNative/launcher-data/characters/<launcher-account-id>/character.glb`. State JSON stores size, hash, part/vertex counts and save time. Children transfer a checksummed file through their own run folder; the parent validates and writes only the associated account. Tokens/cookies stay in the official session and are neither read by the observer nor exported into state or downloadable builds.

There is still no verified direct native account API. Earlier anonymous native/localhost configuration requests returned HTTP 403; historical sanitized evidence is in `outputs/bloxd-public-source/native-auth-capability.json`. No sign-in or token exchange was attempted. This release uses the user-authorized official-window route without impersonating Bloxd for native OAuth.

The local viewer uses [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) and the [glTF format](https://github.com/KhronosGroup/glTF/tree/main/specification/2.0). The Three.js MIT license ships with the viewer. Pure tests use the Khronos validator and synthetic geometry; no client or graphics context is started.
