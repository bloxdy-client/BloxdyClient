# Client status write recovery (0.6.40)

The user reported two Electron main-process error dialogs during normal gameplay on 22 October 2026; gameplay continued. The supplied screenshot identifies `EPERM` from `renameSync(client-updates.json.tmp, client-updates.json)` in `writeRun`, called by `writeUpdates` from the `client:character-status` IPC listener. The reported run directory exists locally. No process holding the file was identified; antivirus, another reader, permissions or another cause must not be stated as confirmed.

Previously, the synchronous rename exception escaped the fire-and-forget IPC listener. Other update callers could also fail, or silently discard the failed publication. This file transfers scoped public account/character status, mod settings, texture status and measurements to the launcher. It is separate from the live gameplay simulation and does not contain authentication cookies or tokens.

`launcher/main.cjs` now contains errors at the status-publication boundary. A failed commit keeps the previous JSON intact and retains the latest combined update in memory. `EPERM`, `EACCES` and `EBUSY` schedule one unreferenced retry timer: 50 ms, doubling to at most 5 seconds. Further updates coalesce while a timer is pending. There is no blocking retry loop, target deletion, direct in-place overwrite or stale snapshot queue. A successful commit resets the delay. Other errors are contained and reported but retry only on a subsequent update or final close attempt.

One bounded diagnostic state per changed error code is written best effort to `client-update-error.json` (`code`, `pending` only), plus a console error. Successful recovery records `code: null, pending: false`. Failure of diagnostics cannot escape either. F9 no longer claims success while the measurement is pending. Close/before-quit cancels the timer and makes a final attempt without scheduling more work. If the write remains impossible at process exit, pending updates cannot be guaranteed saved.

The original atomic rename and parent-only launcher state writes remain. Frame/origin/module/account validation, official login flow, model validation and gameplay rendering are unchanged. This fix does not change the renderer/material milestone, whose overall Iris contract remains incomplete.

Verification uses pure Node/VM mocks and private temporary files. Five regression tests cover rename denial, last-commit preservation, latest-delta coalescing, persistent temp-write denial including failed diagnostics, retry backoff/reset, nonretryable errors, F9 wording, close cleanup and account-identity replacement without resurrecting an earlier character. All five fail against the actual 0.6.39 main-process source extracted from its ASAR; the other 21 main-process tests pass against that baseline. Its injected EPERM stack matches the screenshot's `main.cjs:19:197`, `20:44` and `124:236` path. The full permitted current suite passes 425 tests, 42 syntax files and both generated preloads. No client, account, installer or graphics application is started or controlled. No saved live account/profile data is changed. Real-world recurrence remains a user observation; the identity of the original file blocker is unknown.
